Bug fix plan

The Vanishing Analysis

Switch to the Log tab while a photo is being analyzed — or after it finishes — and everything is gone when you come back. Why the page forgets, and how to give the analysis a memory that outlives navigation.

Symptom: analysis lost on tab switch Root cause: state lives in an unmounting page Fix: context provider in the layout Files touched: 3

01The symptom

Two flavors of the same loss, both reproducible in seconds.

  1. Pick a photo and hit Analyze The skeleton estimate appears; the request to /api/analyze is in flight.
  2. Switch to the Log tab, then back to Analyze The page is blank: no photo, no skeleton, no result. The analysis you paid a model call for never shows up.
  3. Same story after the analysis completes A finished estimate — corrections thread, gram edits and all — also vanishes if you glance at the log before hitting Log meal.
It's not just annoying — it costs money. An in-flight analysis that gets discarded is a completed Claude API call whose answer nobody ever sees.

02Why it happens

Every piece of analysis state lives inside the one component that navigation destroys.

The Home page (src/app/page.tsx) holds everything in local useState: the photo blob, the preview URL, the description, the whole estimate/correction history, the loading flag, plus the resized-JPEG cache in a ref. In the App Router, the root layout survives navigation — the docs are explicit: “On navigation, layouts preserve state, remain interactive, and do not rerender.” Pages get no such promise. The moment you tap Log, the Home page component unmounts and React throws all of that state away.

The in-flight case is subtler. Client-side navigation does not cancel the fetch — the request completes, the response arrives, and setHistory fires… against a component that no longer exists. React silently discards the update. The result was there; there was just nobody home to receive it.

03Options considered

Three ways to make state outlive the page — one clear winner at this app's size.

Surviving a hard reload is explicitly out of scope: it requires serializing the photo, and the meal log already covers "I want to keep this" via Log meal.

04The fix, step by step

Three files. The page's JSX barely changes — only where its data comes from.

  1. Create src/components/AnalysisProvider.tsx A "use client" context provider that absorbs all of Home's state: sourceBlob, previewUrl, description, history, pendingCorrection, loading, error, loggedAtLength, the resizedRef cache — and the functions handleSelect, handleClear, handleLog, analyze, handleGramsChange.
  2. Mount it in src/app/layout.tsx Wrap {children} with <AnalysisProvider>. The layout is a server component and stays one — passing children through a client provider is the standard composition.
  3. Slim down src/app/page.tsx Replace the useState/useRef block with useAnalysis(). JSX, handlers' call sites, and the thread-scroll effect stay as they are.
  4. Move the object-URL cleanup out of unmount Today an effect revokes previewUrl on unmount — correct when the page owned it, wrong once the URL must outlive the page. Revoke only on photo replacement and on handleClear.
  5. Verify both repro paths Switch tabs mid-analysis → result is waiting on return. Switch tabs after a correction thread → thread intact, gram edits preserved.

The provider's shape

// src/components/AnalysisProvider.tsx
"use client";

const AnalysisContext = createContext<AnalysisState | null>(null);

export function AnalysisProvider({ children }: { children: React.ReactNode }) {
  // …all state + analyze/handleSelect/handleLog/handleGramsChange
  // moved verbatim from page.tsx…
  return <AnalysisContext.Provider value={state}>{children}</AnalysisContext.Provider>;
}

export function useAnalysis() {
  const ctx = useContext(AnalysisContext);
  if (!ctx) throw new Error("useAnalysis must be used within AnalysisProvider");
  return ctx;
}

The layout change

// src/app/layout.tsx
<body className="min-h-full flex flex-col">
  <TopNav />
  <AnalysisProvider>{children}</AnalysisProvider>
</body>
Why the in-flight case fixes itself: analyze() now closes over state owned by the provider. Navigation unmounts the page but not the provider, so when the fetch resolves, setHistory updates a live component. Return to the Analyze tab and the page re-reads the context — result present, skeleton logic already handles the still-loading case.
