When the barcode moves

Nothing chases the barcode. While scanning, the frame stays still and the picture moves under it. At the moment of the read, the picture freezes on the exact frame that was read, and the outline flies to wherever the code was in that frame.

What you'll see

  • While it moves: the frame doesn't follow the code. It's only a guide for where to aim. The reader looks at the whole picture, not just the square.
  • Fast movement: the code is blurred, so it can't be read. Nothing happens until your hand slows, which is why steady scans read fastest.
  • The read: the picture freezes on the frame that was read. The outline lands on the code in that still image, so it can never miss.
  • After that: the camera is off. Moving the phone changes nothing, and the product opens.

03Why the outline always lands on the code

The scanner never reads the live video directly. About five times a second, it copies the current video frame onto a hidden canvas and reads that still image.

  1. The read happens on a still copyThe barcode's position comes from that copy. By the time the result arrives, the live video may already have moved on a little.
  2. That same copy is what we freezeOur reader class already receives this canvas (decodeFromCanvas in barcode-reader.ts). On a read, I'd show that canvas over the video. The outline and the picture then come from the same frame and always line up, however fast the jar was moving.
  3. Copy it before stoppingStopping the scanner throws that canvas away, so it gets copied first. It's one drawImage.
  4. The faint flashThe frozen frame can be a moment behind what you were just seeing, so the picture may shift by a few pixels when it freezes. A 13% white flash lasting about 240ms hides that shift and reads as "photo taken". It's optional, and with reduced motion it's skipped.
Why not follow the code live? The outline could only move when a frame is read: a few times a second, and only when the code is sharp. It would jump in steps and vanish whenever the code blurred. Freezing on the read frame is what the iPhone camera and most scanning apps do, and it's what makes the B into C morph look smooth.
