03Database changes

Two new columns: one may stay empty, the other has a default, and today's code never reads either, so the live site on main keeps working while the redesign is on its branch. I'll give you each one in the chat at the step that needs it.

-- Phase 3: which protein level a plan used (null = custom plan or older plans)
alter table public.plans
  add column protein_per_kg numeric(2,1)
  check (protein_per_kg in (1.2, 1.6, 2.0));

-- Phase 6: how often the weigh-in card appears (0 = off)
alter table public.profiles
  add column weigh_in_reminder_days smallint not null default 7
  check (weigh_in_reminder_days in (0, 1, 3, 7, 14));

The snooze from the homepage card stays in the browser (as today's "hide until tomorrow" does); only the interval is saved on the account.

04Build plan

Four phases, built one step at a time: I explain the why, build exactly one step, then stop for you to check it. Each step is checked at 375px and 1280px. All work goes on feat/redesign, with one PR into main at the end.

Phase 1 · Foundations, shell & states

The pieces every page uses, the new navigation, and the screens around the pages.

  1. Design tokens in globals.css (style C colours, radii); Inter only.
  2. Install lucide-react; replace the hand-made icons.
  3. Button component with the five variants.
  4. Sheet component: bottom sheet on phones, dialog on desktop.
  5. Form pieces (field, segmented, choice card) and the toast style.
  6. Top bar: title row, underlined tabs, profile button; AI strip removed.
  7. Desktop sidebar with the pages, AI counter and Settings.
  8. Page layout on every page: no big header, phone column, desktop grid.
  9. App icon I2, favicon, manifest theme colour.
  10. Login, error page, 404, skeleton loading screens.

Phase 2 · Homepage, Log & Products

The pages used every day. They share the meal rows and sheets, so they go together.

  1. Today cards (calories left, protein to go).
  2. Add food block with the AI count; out-of-AI state.
  3. Describe card in place of Add food.
  4. Analyzing card with the live seconds counter.
  5. Estimate card ("After this meal", day + Log) and the corrections card.
  6. Logged state: toast with Undo, new meal highlighted.
  7. Manual add sheet (moves from the Log) and the barcode product sheet.
  8. Eaten today list and the ⋯ meal sheet.
  9. Weigh-in card: save in place, snooze sheet.
  10. Water row, empty day, desktop homepage.
  11. Log: day cards, meals that expand, edit sheet, desktop calendar rail, empty state.
  12. Products: rows, search, edit sheet without the g/ml switch, Log it now, desktop grid, empty state.

Phase 3 · Setup, Stats & Settings SQL: 2 columns

Everything about your plan and progress.

  1. plan.ts: protein levels, goal-weight basis when losing, with tests.
  2. SQL plans.protein_per_kg; save and validate the level.
  3. Plan step UI: maintenance + How we got this, Custom plan card, P1 bar, paces.
  4. Setup steps 1–2 and desktop step 3.
  5. Stats: section switch, range, days on track with the change vs before (tests).
  6. Calendar component: month grids, large dates, tap to open the day.
  7. Average tiles, restyled charts, insight checks (tests) and card.
  8. Weight section: journey + pace estimate (tests), Log weight sheet, smooth trend (tests), weigh-ins.
  9. Water section, Stats empty state, desktop Stats.
  10. Settings list with the plan card and grouped rows.
  11. Body details and Change plan screens (real URLs).
  12. SQL profiles.weigh_in_reminder_days; reminder sheet, wired to the homepage card.
  13. Water toggle with autosave, password and plan-history sheets, desktop Settings.

Phase 4 · Admin & finish

The admin pages, then cleaning up and handing over.

  1. Users: totals, account cards / desktop table, cap sheet.
  2. Account detail: Read-only chip, key numbers, switch, read-only reuse of the new pages.
  3. Dead-code scan: old components, unused CSS and fonts, stale comments.
  4. README and the full manual run-through on a phone and a laptop.
  5. PR from feat/redesign into main when you ask.
Choices I made without asking (say if you disagree): Settings sub-pages are real URLs, so back works; the snooze stays per device; sheets become small dialogs on desktop; old components are deleted only in Phase 9, after nothing uses them.
